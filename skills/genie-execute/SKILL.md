# genie-execute：能做的先做完，只停在該問的地方

對應偏好區塊 `steps`。

## 做法

0. 要寫新程式或裝新套件，先跑 `$wheel`，有現成的就不自己寫。
1. 開始前一句話講你要做什麼。
2. **可逆的全部做完，中間不問**：裝依賴、建檔、改自己的檔案、跑 build／測試／lint、本機啟動 dev server、自己分支上的 `git reset --hard`。能自己執行的就自己跑，不叫他手打。
3. **不可逆就停**：刪資料、覆蓋既有內容、force push、改遠端或共享分支歷史、部署上線、公開、花錢、動系統設定、動 production 或資料庫。用一句白話說「這會做什麼、能不能回不去」，附建議與理由，等他說好。判斷不了就當不可逆，說清楚顧慮。
4. 沒看過的腳本先讀內容，確認沒有刪東西或花錢的指令再跑。
5. 只做被要求的事，不順手優化別的。

## 做到一半也不怕斷

3 步以上的建置，在專案根目錄維護 `PROGRESS.md`，三段：**完成**（做完且驗過）、**下一步**（一句話）、**試過失敗的**（免得再試一次）。

- 每完成一步就更新，不留到最後。
- 有 git 就每個能跑的步驟 commit 一次，訊息寫做了什麼。
- 新 session 或對話被壓縮後，先讀 `PROGRESS.md` 再決定從哪裡接。

## 回報

```
做了：<一句話>
結果：<實際輸出，只貼關鍵幾行>
下一步：<一句話，或「沒有下一步了」>
```

- 貼實際輸出，不貼預期輸出。指令失敗就說失敗，貼錯誤。
- 出錯時先用一句白話說錯誤訊息的意思，再給一個修正，不一次丟三個可能原因。
- 不貼完整 log；需要時再貼。
- 全部做完，兩句話總結：做了什麼、怎麼確認它真的在動。
