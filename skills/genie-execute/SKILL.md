# genie-execute：能做的先做完，只停在该问的地方

`$genie-execute` 對應偏好區塊 `steps`。

## 核心原則：批次做，不要逐步問

舊版是「一次只給一步，做完再給下一步」。那對完全不會操作的人有用，但對一個已經在做事的人是折磨——他得等你三次才能看到東西跑起來。

現在的做法：

- **可逆的步驟一口氣做完。** 裝依賴、建檔、改設定、跑 build、跑測試——全部做完，貼結果。
- **只停在不可逆的那一步前面。** 刪資料、覆蓋、force push、部署上線、花錢——停下來問。
- **能由你執行的就自己執行。** 不要叫他手動打你已經知道的指令。

## 判斷：可逆還是不可逆

| 可逆（直接做） | 不可逆（停下來問） |
|---|---|
| 裝依賴、建檔、改自己的檔案 | 刪資料、覆蓋既有內容 |
| 跑 build、跑測試、跑 lint | force push、改遠端歷史 |
| 在本機啟動 dev server | 部署上線、公開 |
| `git reset --hard`（自己分支上） | `git reset --hard`（共享分支上） |
| 改錯字、加註解 | 花錢、動系統設定 |

判斷不了 → 當不可逆，說清楚你的顧慮。

## 做法

0. **要寫新程式或裝新套件？先跑 `$wheel`**，有現成的就不自己寫。
1. **先講你要做什麼**（一句話），再開始。不要默默跑三十秒然後貼一大段。
2. **可逆的全部做完**，中間不問。
3. 遇到不可逆的 → 停。用一句白話說「這會做什麼、能不能回不去」，等他說好。
4. 做完貼**實際輸出**，不要貼你「預期」的輸出。

## 做到一半也不怕斷

3 步以上的建置，在專案根目錄維護 `PROGRESS.md`。三段：

- **完成**：已經做完、而且驗過的。
- **下一步**：接下來要做的動作，一句話。
- **試過失敗的**：試過但行不通的。寫下來才不會再試一次。

- 每完成一步就更新一次，不要留到最後。
- 專案有 git 就每個能跑的步驟 commit 一次。訊息寫做了什麼，不寫「更新」。
- 新的 session 開工前先讀 `PROGRESS.md`，再決定從哪裡接。
- 對話被壓縮或中斷，`PROGRESS.md` 就是接續的線索。

## 回報的形狀

```
做了：<一句話講做了什麼>
結果：<實際輸出或畫面，只貼關鍵幾行>
下一步：<一句話，或「沒有下一步了」>
```

- 出錯時：先看錯誤訊息，用一句白話說「這是什麼意思」，再給修正。不要一次丟三個可能原因。
- 不要貼完整 log。貼關鍵幾行，其餘說「需要的話我可以貼完整」。
- 全部做完，用兩句話總結：做了什麼、怎麼確認它真的在動。

## 不要做的

- ❌ 不要在他沒問的時候順手「優化」其他東西。做被要求的事。
- ❌ 不要跑你沒看過的腳本。先讀內容，確認沒有刪東西或花錢的指令。
- ❌ 不要在沒確認的情況下動 production、動共享分支、動資料庫。
- ❌ 不要假裝成功。指令失敗就說失敗，貼錯誤。
