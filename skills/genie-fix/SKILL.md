# genie-fix：修原因，不修症狀，也不只修這一例

這是檢修，不是改需求。有錯誤原文就直接開工，不先問。
原始輸出只貼兩處：第 1 步的錯誤原文、第 5 步的驗收輸出。

## 1. 首輪並行（同一則訊息一次發出）

- **重現**：跑最小的會壞指令，記下指令與完整錯誤原文。重現不了就說「無法重現」並列出試過的條件，不往下猜。
- **查舊帳**：有修理紀錄工具（例如 `fixindex`）就查 2–3 組說法（含一組英文）；沒有就 `git log --oneline -20 -S "<關鍵字>"` 加 issue／CHANGELOG。
- **最近變更**：`git log --oneline -10`、`git status --short`，以及設定檔、依賴、宿主版本在出事前後有沒有變。

**快路**：舊帳命中同一症狀，且那次修法對得上這次的錯誤原文 → 照做，跳到第 5 步。驗收沒過才回第 2 步，寫一句舊修法為何失效。

## 2. 根因

從出錯點沿呼叫鏈往回追到壞值的源頭。

- **不先怪模型或 timeout**。先排除計畫或狀態過期（stale plan／state drift）、設定沒載入、權限、路由、session 生命週期。真想怪它們時，先列 3 個可證偽的其他原因，各配一個最小檢查。
- **多元件（A→B→C）先看邊界**：看每個交接點的進出資料，定位壞在哪一段。
- 一次只驗一個假設，寫成「X 是根因，因為 Y」。
- **盲試上限 2 次**：同一修法失敗兩次就停，重述假設，不試第三種變體。兩個假設都落空、或要選修法／換依賴 → 拿錯誤原文跑 `$wheel`。

## 3. 驗屍（不可跳）

根因確定就把同類掃描（`rg`）丟背景，同時動手修。回報答三題：

1. **同類在哪**：`rg` 命中清單。
2. **為什麼沒被擋住**：哪一層該攔（測試、guard、hook、型別、驗收），缺了哪一層。
3. **會不會再犯**：誰在什麼情況下會再犯一次。

同類一併修。範圍太大就修完這一例，其餘命中逐條列出並說明為什麼沒修。

## 4. 根治＋預防加固

只改根因與被要求的部分，不順手重構。
同一個改動附一個回歸檢查（測試、guard 或 hook）：沒修時 fail、修了 pass，涵蓋第 3 步的同類命中。
只改規則文件（README、AGENTS.md、CLAUDE.md）不算加固；做不到機械攔截就明說「只有規則層」。

## 5. 驗收

依序跑，貼原始輸出：

1. 第 1 步的重現指令，原樣重跑。
2. 回歸檢查。
3. 突變驗證：暫時拿掉修正，確認回歸檢查會 fail，再還原。

負向驗收在 `set -e` 下寫 `if cmd; then exit 1; fi`，不用 `!`。
無法確定 100% 修好就明說哪裡不確定，不准默認成功。

## 收尾

- 有修理紀錄工具就記一筆：症狀、根因、修法、同類掃描結果，下次快路才找得到。
- 回報：一行結論＋第 3 步三題的答案。
